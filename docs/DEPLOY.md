# Deploy

Runs on a server instead of your laptop, so the link keeps working when you close the lid and
students on a slow connection still get the page quickly.

One service does everything: FastAPI serves the API **and** the built React app. Students get one
URL, the WebSocket is same-origin, and there is no CORS to configure. Postgres holds the data, Redis
lets several uvicorn workers share state.

```
        one URL
           │
   ┌───────▼────────┐        ┌────────────┐
   │  cybershield   │───────▶│ PostgreSQL │
   │  (Docker)      │        └────────────┘
   │  N uvicorn     │        ┌────────────┐
   │  workers + SPA │───────▶│   Redis    │
   └────────────────┘        └────────────┘
```

## First, onto GitHub

Both managed paths below deploy from a Git repo. If this project has no remote yet, create an empty
repo on GitHub — no README, no .gitignore, it already has both — and then:

```bash
git remote add origin https://github.com/<you>/cybershield-ai.git
```

```bash
git push -u origin main
```

`.gitignore` already keeps `.env`, `*.db`, `node_modules`, `.venv` and the 52 MB `cloudflared.exe`
out. Nothing secret is tracked: the only credentials in the repo are the documented lab logins, and
`JWT_SECRET` is generated by the host.

## Railway

1. Push this repo to GitHub.
2. Railway → **New Project** → **Deploy from GitHub repo** → pick it. `railway.toml` points it at the
   root `Dockerfile`; nothing else to configure.
3. **+ New** → **Database** → **Add PostgreSQL**. Repeat for **Redis**.
4. On the CyberShield service → **Variables**, add:

   | Variable | Value |
   |---|---|
   | `DATABASE_URL` | `${{Postgres.DATABASE_URL}}` |
   | `REDIS_URL` | `${{Redis.REDIS_URL}}` |
   | `JWT_SECRET` | any long random string |
   | `WEB_CONCURRENCY` | `2` |
   | `ENVIRONMENT` | `production` |

   Railway injects `PORT` itself. `ANTHROPIC_API_KEY` is optional — without it the AI explanations
   use the built-in templates.
5. **Settings → Networking → Generate Domain.** That domain is the link you give the class; the
   student page is `https://<domain>/join`.

Railway's Postgres hands out a `postgres://` URL, which SQLAlchemy does not accept. The app rewrites
it to the psycopg driver on startup, so paste it as given.

## Render

1. Push this repo to GitHub (above).
2. Render → **New** → **Blueprint** → pick the repo. `render.yaml` creates the web service, a
   Postgres and a Redis, and wires `DATABASE_URL`, `REDIS_URL` and a generated `JWT_SECRET` for you.
3. Apply, and wait for the first build. It runs `npm ci` and `vite build` inside Docker, so the first
   one takes a few minutes; later ones reuse the layer cache.
4. Add `ANTHROPIC_API_KEY` by hand if you want live AI analysis.
5. The service URL is your class link. Students go to `https://<service>.onrender.com/join`.

**Region.** `render.yaml` asks for `singapore` on all three services, because it is the closest Render
region to India and the round trip is most of what a student on a phone feels. Change all three
together — services in different regions cannot use private networking.

**No card needed.** All three services are on `free`, because a paid plan makes Render ask for a
payment method before it will create anything. The costs of free: the web service sleeps after ~15
minutes idle, so the first student to click a cold link waits about 50 seconds — open the URL yourself
a minute before class and nobody else sees it. And a free Postgres is deleted after 30 days, which is
fine for a term and not for a year. Switching the web service to `plan: starter` removes the
spin-down, and needs a card on file.

**Memory.** The free instance is 512 MB and two workers use roughly 330 MB of it. If the service
restarts by itself, that is the ceiling: set `WEB_CONCURRENCY` to 1. Nothing else has to change —
Redis stays wired either way, so raising it again later is a one-line edit.

**If the blueprint fails validation** on `type: keyvalue`, your account predates the Redis → "Key
Value" rename: change it to `type: redis`.

`CORS_ORIGINS` is deliberately left at its default. The SPA is served by the same service, so no
browser request here is cross-origin and the setting does nothing.

## Any Docker host (VPS, Fly, EC2)

```bash
docker build -t cybershield .
```

```bash
docker run -d -p 80:8000 \
  -e DATABASE_URL="postgresql+psycopg://user:pass@host:5432/cybershield" \
  -e REDIS_URL="redis://host:6379/0" \
  -e JWT_SECRET="$(openssl rand -hex 32)" \
  -e WEB_CONCURRENCY=2 \
  -e ENVIRONMENT=production \
  cybershield
```

Put TLS in front of it (Caddy, nginx, or the platform's load balancer). The app sets HSTS once it
sees an HTTPS request.

## Locally, the full stack

```bash
docker compose up --build
```

Postgres, Redis, four backend workers and nginx. Frontend on **http://localhost:8089**, API on
**http://localhost:8010**.

## Environment

| Variable | Default | Notes |
|---|---|---|
| `DATABASE_URL` | `sqlite:///./cybershield.db` | `postgres://` and `postgresql://` are rewritten to `postgresql+psycopg://` |
| `REDIS_URL` | *(empty)* | Empty means in-process state and one worker |
| `WEB_CONCURRENCY` | `1` | Uvicorn workers. **Needs `REDIS_URL` above 1** |
| `PORT` | `8010` | Injected by every cloud host |
| `JWT_SECRET` | `change-me-in-production` | Set it. Tokens are forgeable without |
| `RATE_LIMIT_PER_MINUTE` | `300` | Per client IP, across all workers |
| `SERVE_FRONTEND` | `true` | Serve `frontend/dist` from the API when it exists |
| `CORS_ORIGINS` | localhost:5173 | Not needed when the SPA is served by the API |
| `SEED_DEMO_EVENTS` | `250` | Backdated demo events on an empty database |
| `ANTHROPIC_API_KEY` | *(empty)* | Optional; templates are used without it |

## What Redis is doing

Each uvicorn worker is a separate process with separate memory. Four things that used to be
module-level dictionaries have to be shared, or four workers give four wrong answers:

| State | Without Redis | With Redis |
|---|---|---|
| WebSocket clients (`ws.py`) | A broadcast reaches only the sockets on the worker that produced it — most of the class sees nothing | Published to every worker, which fans out to its own sockets |
| Detection windows (`detection/state.py`) | Ten brute-force attempts spread over four workers look like two or three each, and no rule fires | One shared sorted set per window, so the burst trips its rule |
| Alert correlation (`pipeline.py`) | One flood becomes four timeline events | One event, whichever worker sees the packet |
| Rate-limit counters (`main.py`) | The effective limit is `N × RATE_LIMIT_PER_MINUTE` | One counter per client per minute |

Two more things are single by nature — the attack simulator and the live attack runner. Exactly one
worker holds a Redis lock and runs those loops; the others forward start/stop over the bus and read
the state from the last broadcast. If that worker is restarted mid-run, press Start again.

Nothing in Redis is worth persisting. `docker-compose.yml` runs it with no disk and an LRU ceiling.

## Sizing for a class of ~100

The traffic is light: one WebSocket per student plus a page load. Two workers on a small instance
have plenty of headroom; the reason to raise `WEB_CONCURRENCY` is a projector-side dashboard being
hammered while 100 students refresh, not the socket count.

Watch instead:

- **Connection limits.** Each worker keeps up to 15 Postgres connections (`database.py`), so four
  workers is 60 — under every managed free tier, but check before going higher.
- **Attack rate.** The Live Attack Range at 600 attacks/minute writes a row per detection. That is
  the only thing here that can actually load the database.
- **`/api/health`** reports `worker`, `leader` and `redis`, which is how you confirm a scaled-out
  deployment is actually sharing state.

## Why the link opens fast now

Three changes, in order of how much they mattered:

1. **The production build is served, not the Vite dev server.** The dev server sends every source
   module separately and unminified — hundreds of requests through one tunnel. `share-with-class.ps1`
   now tunnels the build on port 8010, and a cloud deploy never had a dev server to begin with.
2. **Every screen is its own chunk.** One 1 MB bundle held the entire SOC console — Leaflet, Recharts,
   all seven dashboard screens — and a student opening `/join` downloaded all of it. Now `/join` pulls
   about 110 KB gzipped and the map and charts load only for the operator who opens them.
3. **Gzip and immutable caching.** Hashed assets are cached for a year, `index.html` never, so a
   second visit costs one small request.
